# Akash's Island

An interactive 3D portfolio. A friendly guide robot leads visitors around an open-world island to read about Akash Kumar Singh, or skip to a normal scrolling page with the same content.

Built with React, Vite, Three.js (`@react-three/fiber`, `drei`), Rapier physics, Zustand, Framer Motion and Tailwind CSS.

## Setup and run

Requires Node 20 or newer.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # production build in dist/
npm run preview    # serve the production build
```

Useful URLs:

| URL | Result |
|---|---|
| `/` | Island, or classic view on low-end devices |
| `/#island` | Forces the island on a device that would auto-switch |
| `/#classic` | Forces the classic page |

## Editing your content

Everything visitors read is in [`src/data/portfolio.js`](src/data/portfolio.js): bio, education, skills, projects, milestones and contact links. Both views read from it.

- **Add a project:** add an entry to `projects`. A pedestal appears on the gallery arc automatically.
- **Add a milestone:** add an entry to `milestones`. Stones re-space along the road automatically.
- **Hide a link:** set a project's `github` or `demo` to `null`.
- **Use real screenshots:** put images in `public/projects/` and update each project's `image` and `imageAlt`. The current images are placeholder illustrations.

- **Update your resume:** replace the PDF in `public/resume/`. If the filename changes, update `contact.resume`.
- **Rename a hidden place:** edit `discoveries`. Each key must match a landmark `id` in `src/game/world/layout.js`.

## The living world

Beyond the five portfolio zones there's a wider island with a mountain, a river and waterfall, trails, bridges and eight hidden places to discover.

- **Greeting:** when the island opens, the robot turns to the visitor, waves with happy eyes and says a greeting for their local time. `G` waves again. Edit the wording in `greetings` in `portfolio.js`.
- **Day and night:** the island starts at the visitor's real time of day, then one day lasts 6 minutes (`DAY_SECONDS` in `environment.js`). The sun and moon move across the sky, stars come out, lanterns light up, fireflies appear and the lighthouse beam switches on.
- **Weather:** clear, cloudy, windy, rain, storm and fog change on their own every 1–2.5 minutes. Add or tune a state in `WEATHER` in `environment.js`. A rainbow can follow the rain, and storms bring lightning.
- **Wind:** one wind value drives gusts rolling through trees and grass, drifting leaves, air streaks, flags, the windmill, cloud speed and wave height.
- **Grass:** `Grass.jsx` grows a thick meadow only around the robot, reusing ground cells as it walks. Blades catch the same gusts as the trees and part around the robot. Density is set in `SIZES`, with a lighter version on phones and low quality.
- **Trees:** trunks lean with gusts, branches swing on their own beat and leaves shiver (`addTreeSway` in `uniforms.js`). Sunlight glows through the leaves, and petals and leaves fall from the trees (`FallingLeaves.jsx`).
- **Water:** the sea uses Gerstner waves with depth-based colour, sky reflections, sun glitter, caustics, whitecaps and shore foam. The river flows downhill along its bed, faster in mid-channel and white on the falls.
- **Trees:** pines, oaks, cherry blossoms and palms are generated in `src/game/world/trees.js` from one painted texture atlas, so they add nothing to the download. Foliage between the camera and the character dissolves so the forest stays playable.
- **HUD controls:** visitors can click the clock to skip through the day and click Weather to change it.

`layout.js` holds the trail, river and landmark positions, and the terrain shapes itself around them.

## Contact form

The form uses [EmailJS](https://www.emailjs.com). Until it's configured, the button opens the visitor's mail app with the message filled in.

1. Create a free EmailJS account, add an email service and create a template.
2. Use `{{from_name}}`, `{{reply_to}}` and `{{message}}` in the template.
3. Copy `.env.example` to `.env.local` and fill in the three keys.
4. Add the same three variables in Vercel under Project Settings → Environment Variables.

## Deploy to Vercel

1. Push this folder to a GitHub repository.
2. In Vercel, choose **Add New → Project** and import the repository. Vercel detects Vite, so the defaults work (`npm run build`, output `dist`).
3. Add the EmailJS variables if you use them, then deploy.

Or from the command line:

```bash
npx vercel --prod
```

## Swapping the character

The default character is an original hovering robot generated by `scripts/build-character.mjs`, so it's free to use. To restyle it, change the palette in the `C` object at the top of that file (shell, accent, visor and so on), then run `npm run build:character`.

To use a different model:

1. Get a rigged GLB with idle, walk, run and jump clips (and ideally a wave):
   - [Quaternius](https://quaternius.com): free CC0 animated characters, the easiest drop-in.
   - [Kenney](https://kenney.nl/assets): free CC0 assets, including animated characters.
   - [Mixamo](https://www.mixamo.com): free rigs and animations with an Adobe account. Export FBX and convert to GLB, for example in Blender. Check the licence terms for your use.
2. Compress it:

   ```bash
   npx @gltf-transform/cli meshopt input.glb public/models/character.glb
   ```

3. Update [`src/game/player/characterConfig.js`](src/game/player/characterConfig.js) with the file's `url`, `scale`, `rotationY` and clip names. A wave clip is optional; without one, the character stands idle during the greeting. The character should be about 1.8 units tall with its feet at y = 0.

## Project structure

```
scripts/build-character.mjs   Generates the rigged, animated character GLB
src/
  data/portfolio.js           All site content
  store/useGameStore.js       Game state: panels, visited zones, milestones
  game/
    GameCanvas.jsx            Canvas, physics world and scene assembly
    Systems.jsx               Proximity checks for prompts, zones and milestones
    teleport.js               Minimap travel
    player/                   Controller, camera, input, model, dust, shadow
    world/                    Layout, terrain, environment, water, river, sky, weather, scenery
    zones/                    One component per zone, landmarks, and the shared ZoneMarker
  ui/                         HUD, loading screen, panels, minimap, joystick
  classic/ClassicView.jsx     Scrollable fallback page
  lib/                        Audio, contact form, device detection
```

Zone positions, paths and pedestal layout are in `src/game/world/layout.js`. The terrain is shaped around them automatically.

| Run | Hold Shift | Push the joystick to its edge |
| Jump | Space | Jump button |
| Interact | E | Interact button, or tap the prompt |

| Close a panel | Esc or ✕ | ✕ |
| World map | M, or the World map button | World map button |
| Wave | G | Not available |

## Accessibility and fallbacks

- The classic view is available from the loading screen and the HUD. It opens automatically without WebGL, with software rendering, on devices with 2 or fewer CPU cores or 2 GB or less memory, with data saver on, or if the 3D scene crashes or loses its GPU context.
- Panels trap focus, return it on close, and close with Esc.
- Minimap destinations are keyboard-focusable buttons.
- With `prefers-reduced-motion`, camera lag, wind, waves, birds, the day cycle, automatic weather, lightning flashes and confetti are turned off.

## The house

The About zone is a real room. The door opens as you approach, and the door wall hides while you're inside so the camera can look in from the porch. Rain stops at the roof and outdoor sound is muffled by the walls.

- Laptop: the About panel.
- Bed: sleep until morning.
- Bookshelf: skills.
- Certificate: education and certification.

Furniture positions live in `ROOM` in `src/game/world/layout.js`.

## Visitor bots and the guestbook

Visitors can leave their name when they arrive. Their bot stays where they last stood for 24 hours, and their name stays on the board by the plaza for good. The board also counts everyone who visited, signed or not.

This needs a database. On Vercel, connect Upstash Redis in the Storage tab, which sets the environment variables. Until then the feature hides itself in production. During local development it uses memory, which empties when the dev server restarts.

No IP addresses are stored, and browsers are only known by a random id. Names are filtered in `api/_lib/names.js`, but no filter is perfect, so check the board now and then.

To remove a name, set `VISITORS_ADMIN_KEY` in Vercel, then run:

```bash
curl -X DELETE https://your-site.vercel.app/api/visitors -H "x-admin-key: YOUR_KEY" -d '{"name":"The name"}'
```
